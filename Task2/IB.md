### Исходя из текущих проблем, архитектуры и бизнес-приоритетов в проверочный лист важно включить:
- **Управление доступом** - клиенты видят чужие данные в личном кабинете, некоторые контракты API позволяют внешним пользователям выполнять действия и получать данные, к которым у них не должно быть доступа.
- **Безопасность данных** - контракты API содержат категории данных, которые явно предоставляют персональные данные.
- **Защита инфраструктуры** - гибридная инфраструктура, используется Active Directory — один из главных векторов атаки при взломах.
- **Управление инцидентами** - один ИБ-специалист не успевает покрывать весь ландшафт, nen критично иметь автоматизированные процедуры реагирования.

**Управление оборудованием и физической безопасностью** - можно исключить на этом этапе, описание не содержит признаков проблем в этой области. Центр обработки данных у компании собственный, скорее всего, уже есть базовый физический контроль.
