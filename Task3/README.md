## 3. Cписок требований, которым должны удовлетворить внешние интеграции

### ✅ 1. Требования к безопасности
🔐 **Шифрование данных**:
- Все взаимодействия с внешними сервисами осуществляются только по защищённым каналам связи (HTTPS).

- Серверы обеих сторон должны иметь действительные TLS-сертификаты, выданные доверенными центрами сертификации (CA).

🛡️ **Защита от несанкционированного доступа**:
- Вся передача данных (например, биометрии, номеров автомобилей, прав доступа) должна быть защищена от перехвата, подмены и повторного использования.

- Внутренние сервисы компании (например, smart-access-service) должны верифицировать подлинность сертификатов внешней платформы.

⚠️ **Логирование и аудит**:
- Все обращения к внешнему API должны логироваться (включая дату, время, идентификатор пользователя, тип операции).

- Внешняя платформа должна предоставлять информацию для аудита доступа (кто и когда получил разрешение на вход/въезд и по какому основанию).

### ✅ 2. Протоколы аутентификации и авторизации
🔑 **Авторизация внешнего API**:
- Использование OAuth 2.0 или JWT (JSON Web Token) для авторизации клиентов (в том числе серверов PropDevelopment).

- У каждого клиента (например, smart-access-service) — свой client_id и client_secret, зарегистрированные на стороне платформы «Умный дом».

- Обязательно использование MFA (многофакторной аутентификации) для административных учётных записей, доступа к настройке интеграции и ключей доступа, панели управления доступами (например, назначение прав жильцам).

👤 **Аутентификация пользователей**:
- В PropDevelopment пользователь аутентифицируется в мобильном приложении, и после этого его действия от имени системы подписываются токеном.

- Внешний API должен принимать access token, выданный smart-access-service или централизованным auth-сервисом PropDevelopment.

📋 **Управление правами**:
- Возможность granular доступа: например, пользователь может получить доступ только к конкретному подъезду или конкретному шлагбауму.

- Внешняя система должна возвращать подробные ошибки при нарушении авторизации (например, 403 Forbidden, 401 Unauthorized).

### ✅ 3. Организация взаимодействия между системами
🔄 **Тип интеграции: RESTful API**
Взаимодействие между smart-access-service и внешней платформой будет происходить по REST API с передачей данных в формате JSON.

**Основные эндпоинты**:

 - ```/access/authorize-person```  — авторизация по лицу

- ```/access/authorize-vehicle```  — авторизация по номеру машины

- ```/access/log``` — журнал доступа

- ```/access/rules``` — получение и управление правилами доступа

📡 **Поток взаимодействия**:
1. Пользователь открывает приложение → инициирует действие (вход, проезд).

2. tenant-core-app вызывает smart-access-service.

3. smart-access-service:

- Проверяет локальные правила (в smart-access-db)

- Обменивается данными с внешней платформой (по REST)

- Получает результат распознавания / разрешение доступа

- Приложение показывает результат пользователю (например: «Дверь открыта» / «Въезд разрешён»).

📅 **Синхронизация данных**:
Система PropDevelopment должна периодически:

- Подгружать информацию о новых жильцах и их правах

- Удалять устаревшие данные (например, при выселении)

Внешняя платформа должна поддерживать webhook или callback API для уведомления о событиях доступа.

💼 **Дополнительные требования**
- Внешняя платформа должна быть доступна 24/7, с уровнем доступности не ниже 99.9% SLA.

- Необходимо предусмотреть failover-стратегию: если внешний сервис временно недоступен — действия кэшируются и обрабатываются повторно.

- Вся передача биометрических данных должна соответствовать требованиям ФЗ-152 «О персональных данных».
